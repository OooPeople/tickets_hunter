## 1. 已確認的四項決策

| 項目 | v1.6 |
|---|---|
| 使用 | 只有維護者個人使用，Windows x64／macOS arm64 直接執行原始碼 |
| 測試 | 保留 pytest、mypy、modified-Python、P1／CI／硬隔離及測試 image |
| 舊碼 | 離線驗收、責任接替、獨立覆核與可回復版本成立後即可刪除；真站另由使用者手動驗收 |

## 2. 不變的核心

保留 session 唯一 writer／arbiter／ActiveEffect，Navigation／Purchase／Input／CAPTCHA／Refresh 完整轉移、unknown／quota／停止／晚到結果保護、唯一 native setter、精確 cleanup、必要核心接合、低延遲與資源界線。

保留設定 UI，不以 current 配置無效讓整個設定頁無法打開。資料安全與一般 save／replace 失敗保護不隨升級器取消而移除。`frozen=True` 是 Python 不可變資料模型，不是取消的 frozen 產品成品。

## 4. 案例處置

**153 − 13 ＋ 3 = 143 個 active case ID。**

撤回 G01–G10、P01、P03、H10；不重用這些 ID，不以 skip／空義務／永久 NOT_DUE 佔位。新增 P04（source 資源與 cwd）、P05（source bot/settings 啟動）、H12（離線清理前置）。C01/C02/C04、A04、U10/U12、H09、V13 同步移除原有產品交付部分，保留 current／source／資料保護部分。

其餘 case 下僅屬產品 build／frozen／release 或真站作為工程前置的 variants 也須正式撤回；特別包含 H08 的 converter-only `new-upgrade-tool-file`。必須逐 obligation 核對，不因某個測試檔包含升級測試，就整檔刪除其他必要行為。

[SCOPE_CHANGE_MATRIX_v1.6.json](SCOPE_CHANGE_MATRIX_v1.6.json) 是文件處置索引，**不是**可直接上線的 catalog／execution manifest。新 obligation 總數需依實際 catalog 逐項投影，不能宣稱仍是 341，也不能把舊 P1 的 63/63 當成新矩陣結果。

## 5. 接入只做一次，避免重開 P1

新計劃與新 catalog 的位元組不同於 v1.5；舊核准 digest 不能驗新版。Codex 應以 actual HEAD 保留既有成果，一次同步 scope／ID／obligation／phase／mapping／工具固定常數與直接衝突規範，完成變更範圍覆核與必要回歸，再由維護者核准完整新 catalog digest。

只做需求已批准的變更，不新增通用 verifier 或多版本框架。舊版結果由歷史 SHA／文件保存；後續相同新 catalog 未再變更，就沿用新核准。正式值尚缺時可做既有授權內不依賴出站的工作，不把測試用核准值變成正式 fallback。
